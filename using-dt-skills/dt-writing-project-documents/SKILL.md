# 项目文档录入

负责项目文档的创建、修订与保存。通过当前环境提供的 DEVONthink MCP 读取或写入记录，根据用户所在环境的 MCP 版本和具体接口完成调用和数据保存。

## 文档类型

- 需求澄清、设计、开发计划、开发过程记录、复盘，以及记录或整理实验结果，默认按项目工程状态文档处理。如实记录当前项目状态、已有实现、计划和过程信息，无需反复确认类型。
- 面向外部发布的文档按正式发布文档处理，不得披露 Mock 接口实现、自动化测试等内部工程状态信息，仅保留面向受众的正式内容。
- 若无法可靠判断文档类型，先向用户确认，再开始写作。

## 文档格式

Markdown 优先，用于需求澄清、设计文档、开发计划、交接文档、进度记录等。需要呈现实验数据或者用户明确要求时，使用 HTML。

### HTML 使用要求

1. 使用 `effective-html` 插件完成 HTML 页面的成稿，充分使用图表提升可读性。禁止为了 HTML 而 HTML，或先写 Markdown 再机械地转换成 HTML。
2. HTML 中所有数学公式必须正确渲染。
3. 交付产物必须为可直接在浏览器打开的单 HTML 文件。
4. 不为生成 HTML 编写单元测试，不使用 Computer Use 或 Browser Use 做样式验证。调用插件时保留这些限制，不执行插件中的浏览器样式验证流程。
5. 插件负责页面成稿，最终保存位置和交付遵循本技能的 DEVONthink 执行流程。

## 内容规范

项目文档包括：需求澄清、设计文档、开发计划、复盘、实验结果记录文档。文档内容需要满足如下约束：

1. 除非用户明确要求，否则文档中不得记录包括但不限于“xx项测试已通过”、“新增xx个文件，xx个函数”等开发过程流水账
2. 需要在文档开头记录日期信息，只需精确到日期，无需记录时分秒
3. 规范使用交叉引用：允许使用DEVONthink的交叉引用特性来建立文档之间的链接关系
4. 文档内容（例如：需求澄清、功能设计、开发计划）可能会来自其他技能的输出结果、会话历史总结，这种情况下同样需要满足上述要求，但不能擅改文档的核心内容
5. 每个需求的“需求澄清、设计文档、开发计划” 这三部分，默认放在一个文档中，使用二级标题进行区分。
6. 内容必须忠实反映用户提供的信息和项目已有的客观事实，不得夸大，也不得遗漏已有实现。
7. 不擅自添加“适用边界”“实验边界”“未发现”“不能证明”等限定性表述；仅在用户明确要求或已有客观资料明确包含时记录。不使用“尚未进行 xxx 实验，无法说明 xxx”等免责声明，客观描述事实及对应结论。
8. 默认使用简体中文，代码和术语保留英文。Markdown 正文每个段落保持单行，只在标题、列表、表格、代码块等结构需要处换行，不为控制显示宽度插入硬换行。
9. 涉及文件路径时使用绝对路径；非本机环境需标明是 Ray 集群还是跳板机环境。

### 文档命名规范

1. 项目文档使用需求编号作为开头，例如 `r001-project-init.md` 或 `r002-experiment-results.html`。需求编号严格递增，扩展名与所选格式一致。

## 执行流程

1. 根据本文件`DEVONthink 写入来源守则`章节，获取目标group信息。如果用户未提供任何group，停下并提醒用户。
2. 如果用户只提供了项目 group，则首先在项目 group 下新建 docs 子 group，并提醒用户。已有 docs 则复用，无需重复创建。
3. 按照文档类型、格式和内容规范完成成稿，通过 DEVONthink MCP 将所选格式的文档写入目标 group。
4. 写入完毕后，汇报写入的文件清单。如果创建了 group，一并汇报
5. 如果 MCP 失败，停下并询问用户提供文档写入地址；不使用 Computer Use 等功能启动 MCP，也不擅自写入项目的 `docs` 目录。

## 产物要求

1. 除非用户明确要求，否则禁止擅自为文件或者group打标签

## 交互要求

1. 写入完毕后，必须使用 markdown 链接的方式，显式告诉用户写入的文件地址和 x-devonthink-item，范例：`文档已写入：[Prefill P1 GPU0 GEMM 与 Chunk 验证](<DEVONthink 条目链接>)`。禁止任何静默写入。

## DEVONthink 写入来源守则

Agent 需要从如下来源来获取写入group。如果如下所有来源都没有提供，则停下并询问用户。如果按照优先级检查发现其中一个来源已经有提供，则无需继续遍历，直接使用该来源完成写入。

以下来源严格按照优先级从高到低排序，Agent 必须按照优先级完成遍历：

1. 用户Prompt中直接提供的有效 DEVONthink URL 来源
2. 当前会话历史中提及的有效来源
3. 项目目录的 `AGENTS.*.md`，例如 `AGENTS.env.md`、`AGENTS.local.md`
4. 项目目录的 `AGENTS.md`
5. 系统提供的 `~/.codex/AGENTS.*.md` 文档
6. 系统全局 `~/.codex/AGENTS.md` 文档
