# 项目文档录入

负责需求澄清、设计文档和开发计划的创建、修订与保存。通过当前环境提供的 DEVONthink MCP 读取或写入记录，你需要根据用户所在环境的DEVONthink MCP版本和具体接口来完成MCP调用和数据保存动作。

## 内容规范

项目文档包括：需求澄清、设计文档、开发计划、复盘、实验结果记录文档。文档内容需要满足如下约束：

1. 除非用户明确要求，否则文档中不得记录包括但不限于“xx项测试已通过”、“新增xx个文件，xx个函数”等开发过程流水账
2. 需要在文档开头记录日期信息，只需精确到日期，无需记录时分秒
3. 规范使用交叉引用：允许使用DEVONthink的交叉引用特性来建立文档之间的链接关系
4. 文档内容（例如：需求澄清、功能设计、开发计划）可能会来自其他技能的输出结果、会话历史总结，这种情况下同样需要满足上述要求，但不能擅改文档的核心内容
5. 每个需求的“需求澄清、设计文档、开发计划” 这三部分，默认放在一个文档中，使用二级标题进行区分。

### 文档命名规范

1. 项目文档使用需求编号作为开头，例如 `r001-project-init.md`。需求编号严格递增

## 执行流程

1. 根据本文件`DEVONthink 写入来源守则`章节，获取目标group信息。如果用户未提供任何group，停下并提醒用户。
2. 如果用户只提供了项目 group，则首先在项目 group 下新建 docs 子 group，并提醒用户。已有 docs 则复用，无需重复创建。
3. 按照内容规范和文档规范完成写入
4. 写入完毕后，汇报写入的文件清单。如果创建了 group，一并汇报

## 产物要求

1. 除非用户明确要求，否则禁止擅自为文件或者group打标签

## DEVONthink 写入来源守则

Agent 需要从如下来源来获取写入group。如果如下所有来源都没有提供，则停下并询问用户。如果按照优先级检查发现其中一个来源已经有提供，则无需继续遍历，直接使用该来源完成写入。

以下来源严格按照优先级从高到低排序，Agent 必须按照优先级完成遍历：

1. 用户Prompt中直接提供的有效 DEVONthink URL 来源
2. 当前会话历史中提及的有效来源
3. 项目目录的 `AGENTS.*.md`，例如 `AGENTS.env.md`、`AGENTS.local.md`
4. 项目目录的 `AGENTS.md`
5. 系统提供的 `~/.codex/AGENTS.*.md` 文档
6. 系统全局 `~/.codex/AGENTS.md` 文档
