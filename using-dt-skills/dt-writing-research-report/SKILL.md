# 调研报告

负责调研文档和报告的编写、修订与保存。通过当前环境提供的 DEVONthink MCP 读取或写入记录，你需要根据用户所在环境的DEVONthink MCP版本和具体接口来完成MCP调用和数据保存动作。如果系统环境内DEVONthink MCP不可用，则终止执行。

## 内容规范

本技能的交付产物为人类用户可读的调研报告。内容需要符合以下规范要求：

1. 报告需忠实呈现调研内容
2. 禁止使用“一句话总结”、“心智地图建立”之类的营销术语。调研报告的目的是为用户决策提供信息参考，禁止擅自代替用户总结和决策
3. 所有结论内容只需要根据已有调研信息给出，不允许使用保守陈述、免责陈述，包括但不限于“已有信息关注型号xx/版本xx，但不能说明xx结论适用于所有场景”等陈述
4. 不允许罗列实验数据，不允许未经用户同意记录任何用户所在环境信息、绝对路径、泄漏用户源码目录等信息
5. 交付格式默认使用 markdown。如果用户明确提及其他格式，则必须优先尊重用户的意见
6. 使用二级标题区分调研报告的不同方面的内容
7. 调研报告需要合理使用交叉引用，链接DEVONthink数据库的已有信息，并忠实记录调研来源
8. 如果用户要求保留原始产物，则使用 $dt-source-capture 技能保存原始来源

## 执行流程

1. 按照用户的要求，充分搜索互联网完成调研以及与用户的必要讨论。
2. 形成报告大纲结构，提醒用户进行审核
3. 根据用户反馈结果，进行补充调研，撰写调研报告，按照“DEVONthink 写入来源守则”章节要求写入到指定位置。
4. 如果已有调研报告，比对内容并向用户汇报差异，确认是否需要修改或者追加。如果用户已经明确要求修改和追加，则不允许反复索取用户决策
5. 写入报告后，向用户汇报产物路径

## 产物要求

1. 允许为产物添加2到3个标签，优先使用DEVONthink内已有的标签，如果没有现成合适标签，允许新建。不允许将项目细节例如需求编号等信息作为标签。

## DEVONthink 写入来源守则

Agent 需要从如下来源来获取写入group或者文件。如果如下所有来源都没有提供，则停下并询问用户。如果按照优先级检查发现其中一个来源已经有提供，则无需继续遍历，直接使用该来源完成写入。

以下来源严格按照优先级从高到低排序，Agent 必须按照优先级完成遍历：

1. 用户Prompt中直接提供的有效 DEVONthink URL 来源
2. 当前会话历史中提及的有效来源
3. 项目目录的 `AGENTS.*.md`，例如 `AGENTS.env.md`、`AGENTS.local.md`
4. 项目目录的 `AGENTS.md`
5. 系统提供的 `~/.codex/AGENTS.*.md` 文档
6. 系统全局 `~/.codex/AGENTS.md` 文档
