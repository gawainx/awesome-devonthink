# 项目进度记录

负责在项目专属的`progress.md`文件记录需求完成结果。通过当前环境提供的 DEVONthink MCP 读取或写入记录，你需要根据用户所在环境的DEVONthink MCP版本和具体接口来完成MCP调用和数据保存动作。如果系统环境的DEVONthink MCP无效，则停下并告知用户，不要继续执行

## 内容规范

项目进度记录使用单一 `progress.md` 文件记录需求开发情况和完成情况。内容满足如下规范：

1. 文件内容必须为一个一级列表。每个列表条目为一个需求的进度
2. 使用连续的文字内容记录需求信息以及用户关键决策
3. 条目开头格式为`需求编号(<8位git hash>)`，例如 `- r001(asbdhxfs): 完成skills仓库初始化，用户明确要求使用 npx skills 标准安装方式进行安装`。其中，`<8位git hash>` 表示需求完成并提交更改之后的HEAD hash

### 禁止行为清单

1. 禁止过度记录实现细节，例如“使用MainActor实现了xxx”
2. 禁止记录“xxx项单元测试已通过”、“用户验收通过”这种流水帐信息
3. 用户未验收不得新增条目
4. 禁止修改已有条目的内容
5. 任何场合禁止使用任何换行符、在条目内通过换行来创造新的段落。每一个条目只允许使用一个段落。

## 执行流程

1. 根据 `DEVONthink 写入来源守则` 获取目标文件，预期为单一 markdown 文件。如果存在多个文件，则提醒用户决策，不要使用任何“默认”地址静默写入
2. 如果项目 group 存在，但未创建 `progress.md` 文件，则允许创建空文件，然后继续执行后续流程
3. 读取已有内容的最后一行，获得历史需求编号最大值，并递增作为当前写入的需求编号; 如果是空文件，从 r001 开始。
4. 完成追加写入：只允许写入到文件末尾，禁止写到文件开头、禁止改变已有内容的顺序
5. 按照“禁止行为清单”对写入的内容进行检查，并进行必要的修改。

## 产物要求

1. 除非用户明确要求，否则禁止擅自为文件或者group打标签

## DEVONthink 写入来源守则

Agent 需要从如下来源来获取写入文件。仅使用明确指定为当前项目进度记录文件或项目 group 的来源；其他文档链接不作为写入目标。如果如下所有来源都没有提供，则停下并询问用户。如果按照优先级检查发现其中一个来源已经有提供，则无需继续遍历，直接使用该来源完成写入。

以下来源严格按照优先级从高到低，Agent 必须按照优先级完成遍历：

1. 用户Prompt中直接提供的有效 DEVONthink URL 来源
2. 项目目录的 `AGENTS.*.md`，例如 `AGENTS.env.md`、`AGENTS.local.md`
3. 项目目录的 `AGENTS.md` 
4. 系统提供的 `~/.codex/AGENTS.*.md` 文档
5. 系统全局 `~/.codex/AGENTS.md` 文档
